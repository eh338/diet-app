饮食记录 · 使用说明
==============================

一、三步上线（Netlify Drop，免费）
1. 解压「饮食记录-app.zip」，得到一个文件夹。文件夹里应直接看到 index.html、app.js、data.js、manifest.json、sw.js 和两个图标，不要再套一层子文件夹。
2. 电脑浏览器打开 https://app.netlify.com/drop ，把整个文件夹拖进去。
3. 等 10–30 秒，页面给出一个 https://xxx.netlify.app 地址。手机浏览器打开它，用菜单里的「添加到主屏幕 / 安装应用」。

建议顺手点页面右上角注册并认领这个站点（Claim site）。未登录的匿名站点可能被平台回收；认领后长期保留，免费额度足够个人使用。

二、换地址后的数据迁移（顺序很重要）
1. 先在旧地址打开应用 → 「我的」→「导出 JSON 备份」（也可再导出一份 CSV 存档）。
2. 再打开新地址 → 「我的」→「导入还原」，选择刚才的 JSON 文件。
3. 旧地址的桌面图标删掉，重新添加新地址的图标。
4. 数据存在浏览器的 localStorage，按域名隔离：旧域名的数据不会自动出现在新域名，必须走上面的导出/导入。

三、纯静态托管下不能用 / 受限的功能（如实说明）
- 扫码查条码：可以用。浏览器会直连 Open Food Facts 查询，实测跨域请求返回 200 且能读到商品数据。前提：站点是 https、手机给了摄像头权限，且浏览器支持 BarcodeDetector（安卓 Chrome 支持；iOS Safari 不支持，会自动退回手动输入条码）。
- 断网时：条码查询不可用（必须联网）；搜索、记录、改克数、当天汇总、历史日历、体重、导出 CSV/JSON 全部可用。
- 没有后端服务器，所以：没有账号登录、没有云同步、没有自动抓取新食物、没有 AI 问答或翻译。食谱与建议都在本地计算完成。
- 离线缓存（Service Worker）只在 https 下注册；直接双击 index.html（file://）打开时不会注册，但所有本地功能照常可用。
- 直接双击 index.html 打开时，浏览器通常不给摄像头权限，扫码会失败；请用「手动输入条码」或「自建食物」。
- 数据只在本机：换手机、清缓存、换浏览器或换域名都会丢，请每月导出一次 JSON 备份。

四、数据与备份
- 全部数据存本机浏览器 localStorage（约 5MB，按每天十几条估算可存 3–5 年）。
- 导出 CSV 采用 UTF-8 带 BOM，Excel 可直接打开，含日期列，方便按日期筛选。
- 导入 JSON 会覆盖当前数据，导入前建议先导出一份现有备份。
